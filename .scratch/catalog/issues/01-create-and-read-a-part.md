# 01: Create and read a Part through the API, proven against a real PostgreSQL

**Spec:** [the catalog spec](../spec.md)

**What to build:** The Admin creates a Part through the API, giving its Category, name, manufacturer and part numbers, and anyone with a Login reads it back. A Vendor reads it too, and is refused when it tries to create one. This is the first time the platform stores anything.

It is the first path through every part the catalog needs. PostgreSQL is reached through Drizzle with `pg`, and the API gains its database settings. A first table is made by a first migration, generated from the schema. Domain code returns Effect's `Either`. `core` gains the structured errors that domain code returns. The first entity, Store, Command and Query are built in the shape ADR-0004 describes, for every later module to copy. The API's tests against a real PostgreSQL are run by a new command, `pnpm integration:check`, in a container that the tests start themselves.

A Part has no specifications yet (ticket 03), and there is no search (ticket 06) and no photo (ticket 07). Nothing here touches the development database. Ticket 02 applies the migrations there and runs the API against it.

**Blocked by:** None (can start immediately)

## Comments

### 14 October 2026: completed

**For the owner to decide.**

- **The API now refuses to start without its database password, and nothing gives it one yet in development.** `pnpm exec nx serve @pcp/api` and `pnpm platform:check` fail at the API's start until ticket 02 supplies `DATASOURCE_PASSWORD` from `.env`. `pnpm check` and `pnpm integration:check` are not affected. **My recommendation:** ticket 02 is next, before anything that needs the running API.
- **Every request is now checked against its Request class, across the whole API, and a field the class does not declare is refused.** The ticket asks for refusals naming the field. Refusing unknown fields came with the same set-up (NestJS's `whitelist` and `forbidNonWhitelisted`), and a test holds it. It also means ticket 05's edit refuses a Category instead of ignoring one. Ticket 15 now records it as a convention.
- **The answer does not carry the times a Part was created and last changed.** The table holds both. Ticket 05 needs the time of last change to be seen, and adds it to the answer then.

**What the documentation says, for the releases installed.** Nothing was copied from the workplace's repository.

- **Drizzle ORM 0.45.4.** Its online documentation now describes 1.0, which is a release candidate, so the installed package's own types and code were read instead.
  - `drizzle({ client: pool, schema })` takes an existing `pg` pool.
  - `migrate(db, { migrationsFolder, migrationsTable?, migrationsSchema? })` keeps its record in the schema `drizzle`, table `__drizzle_migrations`.
  - It applies every pending migration in one transaction, and decides what is pending by the time in the journal.
  - It needs `meta/_journal.json` in the folder, and fails without it.
- **drizzle-kit 0.31.11.**
  - `generate --name <name>` writes `NNNN_<name>.sql`, numbered from `0000`, with a snapshot and a journal under `meta`.
  - It needs a dialect, the schema's files and the output folder, and no database.
  - It has a `check` command for the migrations folder. Ticket 02 decides whether that is how `pnpm check` finds a schema change with no migration.
  - It loads the schema's files by itself and knows no path alias. The Part's schema therefore imports the domain's Category by a relative path.
- **Effect 3.22.2.**
  - `Either<Right, Left>`, with `right`, `left`, `map`, `flatMap`, `match` and `getOrThrowWith`.
  - Effect 4.0.4 exports no `Either` module, as the spec says.
- **Testcontainers 12.2.1.**
  - `new PostgreSqlContainer(image).withDatabase().withUsername().withPassword().start()`.
  - The started container gives its host, its port and its connection address.
  - A helper container, `testcontainers/ryuk`, removes a container that a run left behind. It is downloaded from Docker Hub on first use.
- **The workplace's documents** on layers, application patterns, errors, Drizzle, migrations and tests were read. Differences:
  - The error body stays as this API had it: no trace identifier, and `additionalInformation` only when there is something in it.
  - An error's title and detail keys are made from its code, as the API's existing errors already were.
  - Tests of an endpoint go through HTTP with `fetch`, as before, and not with supertest. Nothing is mocked.
  - The workplace keeps a shared test database in its core library, and so does `@pcp/core/test-utils`. Its container is started once for a run in Jest's global set-up, which gives the API's settings the container's address.

**How it was built.**

- **Install scripts.** Testcontainers brings three, and none is run:
  - `ssh2` and `cpu-features` compile optional native code with node-gyp, and `ssh2` falls back to plain JavaScript. SSH is only for a Docker host on another machine.
  - `protobufjs` only prints a warning.

  The reasons are in `pnpm-workspace.yaml`.
- **The target.** Nx's `@nx/jest:jest` executor printed that it is deprecated and will be removed in Nx 24. The target, named `integration`, therefore runs Jest through `nx:run-commands`. Jest printed no test names when it was not run in a terminal until `--reporters=default` was given.
- **`@jest/globals` in the test helpers.** Jest refuses `@jest/globals` outside a test file, and the global set-up loads `@pcp/core/test-utils`. The assertion helpers therefore read Jest's global `expect` instead of importing it. The entry stays single.
- **Formatting.** The folder drizzle-kit writes, `apps/api/src/drizzle`, is excluded from Oxfmt, like the generated client.
- **Categories.** A PostgreSQL enum made from the domain's eight keys.
- **Identifiers.** An identifier that is not a UUID is answered 404 like any missing Part, and is never sent to the database, which would refuse it.
- **OpenDB IDs.** OpenDB's data model notes say each record's `opendb_id` is a UUID that matches its file name, so the column is a UUID. Ticket 08 now also refuses a record whose ID is not one.
- **The code review.** It found:
  - part numbers given as null answered 500 instead of 400;
  - a name and a manufacturer trimmed before they were stored, where the spec says "stored as written";
  - a `throw` in the Store's conversion of a row;
  - the same conversion of the settings into a connection written twice;
  - the refusal bodies written out in three test files.

  All are corrected. Its notes on conventions that changed are now in ticket 15's checklist.

**Fault checks.** Each was planted by a script that refused a dirty tree, made one exact edit, ran the tests and undid the edit. `git status` was clean after every one.
