# Spec: Redesign

Status: resolved
Category: enhancement

A short hand-over, written on 21 October 2026 when the design skills were set up. The redesign session triages it, settles its open questions with the owner and writes the full spec and tickets. It follows [docs/agents/design-skills.md](../../docs/agents/design-skills.md) for which skill leads which area.

## Problem Statement

The owner finds the dashboard cold, linear, rigid and without taste: it reads as made by an AI, though Impeccable designed it. Part of the cause is written into [apps/dashboard/DESIGN.md](../../apps/dashboard/DESIGN.md) itself: screens "in the manner of Linear", "nothing that moves without reason", flat surfaces, stock Geist, and no motion section. Taste's chapter on app screens names stock Geist among the marks of "a well-applied kit, not a product with its own identity". The Shopper app has not been built far yet, and the owner wants it designed the same new way so that it does not end up the same.

## Order agreed with the owner

1. **Capture the current dashboard and critique it.** The Catalog, a Part, the Vendors, the portal's Offers and the Offer form, at phone and desktop widths, in English and Kurdish. Beside each screen, Taste's findings (its redesign audit and `inspect.mjs --app`), Emil's review and Impeccable's critique, rendered in the built-in browser for the owner.
2. **Review the hard rules against the skills.** Go through the root [DESIGN.md](../../DESIGN.md)'s floor and PRODUCT.md's Accessibility & Inclusion with the owner, and keep, adjust or drop each rule where it makes screens rigid. WCAG 2.2 AA is the owner's standard and is not part of this review unless the owner reopens it.
3. **Decide whether "the Rate Board" stays.** The idea of figures on graphite plates, taken from Erbil's money changers, is the kind of subject-born concept Taste asks for; the critique shows whether the execution or the idea is at fault.
4. **Deal directions and choose.** Taste's `draw.mjs --app --keep type` for the dashboard, with pictures of Erbil from `assets.mjs`, each option rendered with realistic, obviously fictional data, and chosen by the owner by eye.
5. **Rewrite the dashboard's DESIGN.md** with Impeccable, and an ADR that replaces the parts of [ADR-0007](../../docs/adr/0007-a-look-and-components-for-each-app.md) it changes. Motion gets its own section, led by Emil's skills.
6. **Build it**, screen by screen, in tickets.
7. **The Shopper app the same way**, through Taste's page run for its public pages.

## Settled in triage

The owner settled the hand-over's three open questions on 21 October 2026.

- **The inspector logs in itself.** `inspect.mjs` launches one Chrome and opens a tab for each width in one profile, and Keycloak keeps its session in a cookie on its own address, so one login before the first tab carries to the rest. A script of the project's own wraps the inspector's launch of Chrome, logs in as the development Admin from `.env`, and then runs `inspect.mjs` unchanged; Taste's files are not edited, so `npx skills update -g` cannot undo it. The Vendor portal's screens are reached by acting as a Vendor, so one Login serves both halves. It is untested whether Keycloak's redirect back finishes inside the inspector's wait of about two seconds after load; the first ticket proves it, and snapshots of the screens are the fallback if it does not.
- **Fictional data is faked API answers.** One fixture of an obviously fictional shop, a Vendor with about a dozen Offers in every state (confirmed today, older, about to expire, expired, out of stock, no warranty stated). The same script answers the dashboard's calls for Vendors and Offers from it inside the inspector's Chrome, because the API stamps a Confirmation with the moment it is made, so no Offer about to expire or expired can come through it, and the development database holds the end-to-end tests' leftover Vendors. Catalog Parts still come from the API, since they are real (ADR-0001). Nothing is written to the development database.
- **The fonts stay.** The owner finds the typefaces fine and the design at fault. Geist, Noto Sans Arabic and Geist Mono stay, ADR-0006 is untouched, and every draw keeps the type.
- **No capture test.** The inspector photographs each screen at 1440, 768 and 360 pixels, and the language is in the address (ADR-0008), so one run per screen in English and Kurdish gives both the captures and Taste's findings, which Emil's review and Impeccable's critique then read.
